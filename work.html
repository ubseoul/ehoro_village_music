A five-model AI production program

Program delivery · AI workflow design · release management

The problem
Ship a large narrative game (Rich Alucard) fast, using several AI models, without losing control of quality or decisions.
What was done
Directed five AI models (Claude, ChatGPT, DeepSeek, Gemini, Codex) as a production team with phase gates, a decision log, documented handoffs and a release process.
Result
A 113-adventure narrative game shipped in about three weeks. Play the public build →
What it shows
Running a multi-stream program with clear gates, owners and checks: the same discipline teams need to adopt AI safely.

Ehoro Village

Quality audits that restored trust

Risk · verification · reporting

The problem
Automated tests were reporting success while 6 of 9 game modes did nothing at all.
What was done
Designed audits that checked real inputs and outputs instead of test status, and added verification checks to the release process.
Result
Status reports that could be trusted again, and a habit carried into every later program: verify, don't trust.
What it shows
Catching a critical reporting risk before it shipped, which matters more as teams lean on AI-generated work.

A documented AI-assisted method

Process design · documentation · enablement

The problem
AI-assisted work is easy to start and hard to repeat: every new session forgets the last one.
What was done
Documented a reproducible method across 24+ build sessions: goals, quality checks and handoffs between tools, so each new session starts consistently.
Result
Each new session starts consistently, without rework. The same standards are what Ehoro Village's workshops teach.
What it shows
Turning individual AI use into a team practice: standards, documentation and training.

Ehoro Village

An onboarding learning module

Learning design · instructional design

The problem
New users drop off when onboarding explains instead of letting them practice.
What was done
Designed an onboarding module using action mapping and Bloom's taxonomy, with branching scenarios and narrated audio.
What it shows
Learning design that starts from what people need to do, not what they need to be told.
